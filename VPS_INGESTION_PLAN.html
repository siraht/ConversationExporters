One pipeline, with separate durable checkpoints

Provider tabs → extension archive → native-host committed generation
→ local ASM transport spool → SSH verified ready batch
→ VPS ASM raw blobs + portable conversations → CASS lexical index
→ separately scheduled semantic catch-up

Browser authentication stays in provider tabs. The native host uses the existing operating-system SSH configuration; no SSH private key is placed in the extension. Browser closure stops new capture but must not prevent already-committed local exports from being delivered by a user timer.

Use the existing ASM snapshot/push/receipt protocol rather than inventing another uploader or queue. A small local ASM metadata/blob spool is acceptable for this reuse; do not run local web normalization, CASS indexing or semantic models. First measure temporary disk amplification with a representative export. If the existing snapshot API forces expensive duplicate retention, fix that narrow capture boundary rather than introducing a second protocol.

Configure host alias, remote archive root, machine identity, account identity and local export/spool paths. No runtime default should silently assume this particular VPS. Keep accounts and workspaces distinct; display labels must not merge separate accounts. A dedicated web-export source identity avoids the current native-only snapshot policy, which deliberately excludes web exports.

Security, load and scope boundaries

Begin with one transfer and one locked ingestion worker; independent browser provider work can remain concurrent. More index writers would compete for the same database and VPS memory. Index once per drained batch of changes using the existing delta tracker, not once per uploaded file. Bound queue draining so failures cannot monopolize a service invocation.

Use the mounted archive filesystem's available space for backpressure, with a configurable minimum and room for staging overhead; do not revive an unexplained fixed reserve. Stop accepting new generations before capacity is exhausted, retain pending data locally and report the condition. Do not automatically purge archival originals to make room.

Use SSH host verification, private spool permissions and redacted errors. Prefer a dedicated upload identity constrained to the archive intake and receipt commands; it must not gain arbitrary privileged systemctl access. Do not copy provider cookies, browser profiles or credential stores. Reuse ASM path/hash validation rather than treating remote filenames as trusted shell fragments.

Direct HTTPS remains the no-companion option for other users. Later, connect it to the same committed-generation intake and receipts, with destination-aware state, bounded requests and limits. Do not deploy a public API, message broker, container stack, new database or rclone dependency just for the SSH installation.
