Acceptance contract

Export every conversation the connected provider account exposes, across all supported organizations/workspaces, normal history, archived history and projects where exposed. Preserve complete retrievable message trees, settings, attachments and generated assets. Never restrict by date. Preserve previously downloaded records. Discover new chats and revisit changed chats on subsequent syncs without duplicating stable identities.

Inventory completeness, content completeness, archive freshness and successful replication are separate facts. A downloaded/discovered ratio alone cannot prove discovery completeness. Missing scopes, malformed responses, truncated pagination, expired assets and inaccessible records must remain explicit failures or limitations; they must never become a green “everything” claim. Deleted, temporary, expired or otherwise unexposed provider content cannot be reconstructed, and must not be promised.

Implementation sequence and cost controls

  1. Fix silent data loss and false success first, in independent provider and orchestration changes.
  2. Test concrete failure cases with synthetic fixtures. No private exports, tokens, chat titles or account data enter Git.
  3. Integrate status reporting and create final builds. Re-run tests only after relevant changes or actual failures.
  4. Review this matrix at integration and handoff. Every open item must have a specific limitation or next action; no new framework, database, dependency or telemetry service is needed.
  5. Leave provider endpoint uncertainty to explicit live evidence instead of inventing undocumented API behavior. User manually verifies the final extension.

Decisions and lessons

  • A safety limit is acceptable only if reaching it produces an incomplete result; returning a partial list as success is not acceptable.
  • A provider's terminal response is evidence of enumeration completion, not independent proof that its private API exposes every product feature.
  • Missing update timestamps are unknown freshness, not evidence that a chat is unchanged.
  • The original local project path was absent on this machine. Restored the published repository at /home/travis/Projects/ConversationExporters; no private archives were restored or modified.

Known boundaries requiring live evidence

  • Claude's bare-array responses lack an explicit total. Next links are followed when supplied; live oldest/newest/project checks are needed to identify any unexposed history.
  • Gemini has no verified detail continuation contract beyond returned turns/candidates. Hitting its turn limit now fails explicitly and preserves the partial attempt separately. Hidden branches cannot be promised.
  • AI Studio's returned detail is opaque. The full response is preserved, but semantic prompt/asset completeness requires comparison with known prompts.
  • Connected browser sessions determine account scope. Automatic switching among unrelated logins is not implemented. Deleted, expired and temporary content absent from provider endpoints cannot be recovered.
  • Byte limits remain explicit errors for oversized assets and ZIP generation. Use replication for archives above the ZIP limit; no truncation is silently accepted.
  • Browser shutdown/reload interrupts a run. Successful records survive and the next run re-enumerates/reuses eligible records. Cancellation finishes at request boundaries, except Grok asset transfers which are abortable.

Manual handoff checklist

  1. Load packages/unified-extension/dist/firefox/manifest.json in Firefox/Zen, or load the dist/chrome folder unpacked in Chrome. Use version 0.4.0.
  2. Refresh signed-in provider tabs. Open AI Studio History and one saved prompt. Start the first sync manually to grant media permissions.
  3. Run providers individually or use Sync all. You may close the dashboard; reopen it to inspect persisted progress. Claude/Gemini deliberately refresh legacy capture markers once because prior validation was weaker.
  4. Compare known oldest, newest, archived and project conversations with the output. Check any reported missing assets, malformed endpoints or truncated details. Stored/inventoried equality is not sufficient.
  5. Download the combined ZIP and inspect reports and a few known conversations. If replication is configured, verify one receiver copy.
  6. For incremental behavior, add a new ordinary chat or append to an existing test chat, then sync that provider once. Confirm the change appears under the same identity without duplicating it. This is the only deliberate repeat needed for freshness acceptance.
